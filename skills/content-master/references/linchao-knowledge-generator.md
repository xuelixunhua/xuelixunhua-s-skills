# 林超式知识生成器参考

本 reference 保存“材料怎样变成长期可调用知识框架”的深层方法。它不增加学科工具，也不重新决定输入成熟度、删减强度和来源归属；这些边界由调用它的 [笔记处理方法](note-processing.md) 先行确定。本文件集中保存结构关系、分类、模型和案例推导的检查，不再重复来源清点与覆盖流程。

## 与跨学科 Toolbox 的边界

- **Toolbox 回答用什么看**：系统、供需、工程、信息、心理、网络位置或其他分析工具怎样帮助理解现实问题。
- **知识生成器回答怎样组织材料**：如何从叙述和清单中抽出核心抓手、核心问题、逻辑递进、结构化展开、方法和使用方式。

工具选择可以改变结构判断，但工具名不能成为正文骨架。一个学科概念只有在带来新对象、新变量、新机制或新边界时才进入框架。

## 七种材料加工角色

这不是必须填满的模板，而是用于判断材料中缺少哪种结构角色：

1. **进入视角**：从什么现实问题进入，这份材料位于哪一层；
2. **核心抓手**：哪个概念、矛盾或机制能够统摄最多内容；
3. **核心问题**：材料可以持续回答什么问题，而不只是原章节叫什么；
4. **逻辑递进**：概念、事实、案例、机制和结论怎样推进；
5. **结构化展开**：主体各部分分别承担定义、现象、机制、方法、证据或边界；
6. **方法抽象**：哪些关系可以迁移为诊断、判断或行动工具；
7. **使用方式**：未来遇到现实场景时先问什么、看什么、怎样行动。

材料不支持的角色可以省略。维度数量由内容自然生成，不为凑齐七项制造章节。

## 找到核心抓手

核心抓手不是主题词，也不是最响亮的概念。它必须能够改变材料的组织方式。可用四个问题寻找：

- 这份材料真正反复处理的对象是什么；
- 哪个矛盾或机制连接了最多分散段落；
- 哪个概念能够解释最多下游事实和方法；
- 未来读者遇到现实问题时，会用什么词重新找到这份知识。

如果只能写出“这部分讲 A、B、C”，却说不清它们共同服务什么问题或查用任务，还没有找到抓手。并列参考框架可以成立，不必硬造一条因果链；若某个抓手只能靠删除大量反例或独有信息维持，它也不成立。

## 把章节名改造成核心问题

来源目录说明作者怎样发布内容，不一定说明读者以后怎样调用。把静态名词转成可持续追问的问题，例如：

- 一个系统怎样把输入变成结果，在哪些环节失效；
- 某种能力如何形成，哪些条件会限制它；
- 一个关系如何被观察、验证并转成行动；
- 一项方法解决什么问题，什么时候不应使用。

核心问题要能统摄所属材料，也要允许反例和边界进入。不能把预设答案伪装成问题。

## 压出逻辑递进

逻辑递进不是标题从抽象到具体，也不是把条目排成一、二、三。先给内容单元标注角色，再判断关系；可能是真正递进，也可能是并列、包含、约束、互补、冲突或反馈，不能把所有关系写成先后：

- 定义为后续判断提供对象和口径；
- 现象说明问题怎样表现、影响谁；
- 机制解释为什么发生；
- 证据支持、修正或限制机制；
- 方法针对已确认的机制和约束；
- 案例展示机制怎样运行或在哪里失效；
- 边界说明结论依赖什么条件。

常见展开可以是：

> 核心定义 → 现象与影响 → 机制解释 → 抽象解决方法 → 具体实现路径 → 使用边界

也可以采用问题链、时间链、对象链、因果链或行动链。横向框架按共同问题展开，独立参考项按查用任务组织，不虚构后一节依赖前一节。每部分要能说明在整体中的功能；有真实阶段依赖时才写 `输入 -> 本节判断或结果 -> 下一步用途`，没有依赖时说明它与其他部分共同支撑什么。

建立结构假设时，可以用一句话试查：“这部分服务于什么问题，哪些对象或变量以什么关系形成解释，证据和边界放在哪里？”这句话是内部检验，不是必须写进正文的开场白；未证实的联系标为假设，不能把整理者的重构冒充来源结论。

## 结构化展开

面向读者型主体优先使用能直接调用的机制名、问题名、阶段名和判断名；原始标题若本身清楚、存在真实结构，或已被用户锁定，直接保留。来源记录型保留其必要目录与归属，面向读者型只在追溯有价值时保留章节名、编号和作者名，不制造两个完整的正文入口。

结构化不等于增加分类。下面是一处集中检查，按当前文本实际使用的结构选择，不要求没有公式的笔记也做公式验收：

1. **对象与功能不混层**：分清观察信号、解释变量、机制、能力、资源、结果、证据和边界；判断它们是被讨论的对象，还是解释对象的手段与依据。
2. **同级分类同轴**：真正的并列类别回答同一个分类问题。A 讲“如何获得收益”、B 讲“谁承担成本”、C 讲“拥有什么资源”，不能当作同一轴上的互斥类别；可以改成解释同一对象的不同维度。因果、反馈与价值冲突不强迫彼此排斥。
3. **基础维度与复合模式分开**：维度负责描述，模式由多个维度的稳定组合生成；不能先发明人物、组织或策略标签，再拼凑维度为标签辩护。
4. **公式与概念可回指**：公式、模型或总括句中的名词应有清楚、一致的定义，能够对应观察或判断动作；未定义的“资产、风格、状态、能力”不能突然进入公式。新符号在使用前或就地解释，不用后置术语表弥补推理断点。
5. **交叉影响但单一维护**：一个单元可以影响多个维度，明确主要归属和次级影响，用回指调用，不在多个章节重复完整维护。
6. **局部成立且整体有用**：检查上下统属、同层口径、前后联系和整体覆盖；真实递进要有承接，横向结构要有共同问题，参考项要有查用位置。无法说明作用时先重排或合并，保全内容不能因当前架构容纳不了就删除。
7. **关系写到内容里**：递进要增加深度、条件或行动层级；因果要有机制、必要条件及证据边界；约束要说清谁限制、校正或抵消谁。只写“互相关联”不能通过。

案例按功能进入：支持机制、提供反例、展示最小数字推导、说明边界或帮助理解。重复承担同一证明作用的可以合并；承担不同功能的不能因篇幅长而删除。能演示机制的案例未必能证明机制普遍成立。

发现错层、公式无法回指或章节悬空时，先修内容角色与归属，必要时回到来源核对；暂缓的是把问题当成已解决的正式成文，不禁止带明确假设的结构试写。

## 清单、图片与单篇的重构示例

设计书和方法书常把角色、空间、临场感、美学氛围、原则、技巧、镜头、工具与检查项列为二级目录。先问它们共同解决什么设计问题，再辨认设计对象、影响变量、结果感受和操作手段；不能只把清单分成几个更大的桶。

以游戏设计为例，可以检查这些材料是否解释玩家如何形成行动理由、系统如何产生情绪、空间如何承载选择。目标与反馈、空间约束与临场感、规则压力与情绪释放之间是否有依赖；自由度与叙事控制、信息量与决策质量之间有什么约束，都要由原文支持，不能预设方向。

“角色、空间、临场感、美学氛围”可能共同构成一种体验解释：角色让世界社会化，空间把行动约束具象化，临场感把玩家身体放进场景，美学氛围统一感官解释。这是结构候选，不是通用定律；原文不支持时寻找实际关系，也允许它们作为不同设计维度共同解释体验，不硬套生成链。

标题可以像 `《权经》：从授权链到退场的权力方法论` 一样直接呈现架构判断，但须得到正文支持。开头可以给总判断或必要的主线图，不写处理说明；机制名、阶段名或问题名优先于无调用价值的来源标题。图片也要提取其对象、关系、层级、流程或反馈，图片链接、编号、镜头名、法则名和原始小标题承担必要追溯。

维度由材料自然生成，真实结构只有两项就保留两项；太碎时检查缺少什么统摄关系，太少时检查是否压扁独有内容，不按 3、5、7 的数字凑章节。

## 谨慎做方法抽象

方法必须能够迁移到其他对象，并帮助读者诊断问题、识别变量、判断取舍或指导行动。可以用四个问题验收：

1. 它解决什么类型的问题；
2. 它依赖哪些前提、资源或证据；
3. 它包含什么判断或动作；
4. 怎样识别它有效、失败或不适用。

不要把只在原材料内部成立的概念、生活启发、表达技巧、案例结论和零散建议全部升格为方法。一个方法讲透，比多个方法名并列更有价值。

## 落到使用方式

好框架不仅说明“材料讲了什么”，还要说明以后怎样调用。使用方式可以写成：

- 一组诊断问题；
- 一条从观察到判断的链；
- 一个行动流程与反馈节点；
- 现实场景到对应章节的入口；
- 一组适用条件、风险和反例。

使用方式必须由前文结构推出。不能在结尾突然增加与材料无关的建议，也不能把所有知识强行翻译成行动清单。

## 不同规模材料的输出重心

### 单章或单篇

优先形成核心抓手、核心问题、逻辑递进、结构化解释和使用入口。方法抽象只有在材料真实支持迁移时才出现。

### 长书、课程或系列

优先形成总框架、各单元在总框架中的功能、跨章节机制链、反复出现的边界和长期更新入口。不能为每章生成平行摘要后停止。

### 多来源主笔记

优先形成面向现实问题的统一入口、共同机制、冲突判断、适用边界和调用路径。来源目录不支配正文结构；具体保全、映射和覆盖审计服从 `note-processing.md` 已确认的边界。

## 压力测试

拟将框架推广到多种对象或高后果场景时，用有区分力的样本检验，而不只挑支持它的例子。优先覆盖正向、负向和优缺点并存的复杂情形；这三类是选样方向，不是每次必须凑齐的配额。已有反例足以暴露缺口时先修框架，材料不足时说明尚未验证的边界，不编造真实案例补数。

对案例补齐支撑当前论证所需的环节：

> 可观察事实 → 候选解释 → 验证条件 → 行为或结果变化 → 当前判断 → 对应行动

不是每个案例都必须走到行动；用于辨析时可以停在当前判断或仍不可区分的解释。不能由模糊表情或一句话直接推断人格、动机和关系；补充的假设例子只用于检查内部一致性，不构成现实有效性证据。

框架若只能解释成功案例、必须跳过中间推导，或每遇到反例就增加一个新标签，说明抓手或分类仍不稳定。保留原始事实与冲突，不为维护漂亮结构消除不确定性。

## 质量门槛

- **不是摘要堆叠**：能回答通过什么结构解决什么问题；
- **不是工具名展览**：每个概念带来新增解释；
- **不是过度抽象**：承担解释、证据和边界功能的细节仍然可见；
- **不是模板填空**：材料不支持的栏目省略；
- **不是双重入口**：面向读者型由清楚的知识名称承担理解，来源名作必要追溯；来源记录型和用户锁定标题遵守既定边界；
- **不是过程汇报**：最终正文直接呈现知识，不描述整理任务；
- **可以调用**：现实场景能够找到对应问题、解释或方法及其边界；仅在用途需要时提供下一步。
