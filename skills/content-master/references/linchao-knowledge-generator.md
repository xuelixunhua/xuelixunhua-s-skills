# 林超式知识生成器参考

这个 reference 用于补足 `cross-disciplinary-thinking-toolbox.md` 的另一面：Toolbox 负责选择分析视角，本文件负责把一份材料加工成可复用的知识生成器。

它不是第二套跨学科工具箱，也不替代原始材料。只有当任务需要把课程、书、系列材料、逐篇笔记或多来源素材沉淀成长期可调用框架时，才读取本文件。

## 与 Toolbox 的边界

- **Toolbox 回答用什么看**：现实问题适合用系统、供需、工程、信息论、心理学、社会网络，还是其他工具。
- **知识生成器回答怎么整理**：一份材料如何从原始叙述变成进入视角、核心抓手、核心问题、逻辑递进、结构化展开、方法抽象和使用方式。
- **两者可以联动**：Toolbox 选出主工具后，如果输出仍然像概念清单，就用本文件把材料加工成可阅读、可调用、可迁移的知识结构。

不要因为本文件也涉及“知识生成”就把它当成新的工具库。它的核心任务是组织材料，而不是增加学科概念。

## 什么时候读取

读取本文件的典型信号：

- 用户要求“知识结晶”“主笔记”“总纲”“机制图谱”“融会贯通”“可调用框架”。
- 输入是课程、长书、系列文章、逐篇笔记或多来源材料，直接摘要会变成章节堆叠。
- 压缩版 Toolbox 已经选出工具，但还不知道正文该如何展开。
- 材料有大量案例、概念和方法，必须区分核心定义、现象、机制、解决思路、具体路径和使用方式。
- 用户要求长期维护某个主笔记，而不是生成一次性总结。

不必读取本文件的情况：

- 用户只要保留事实、会议纪要、转写留档或轻量摘要。
- 当前任务只是改标题、润色、格式整理或局部补写。
- 已有成熟目标文档明确给出结构，照目标文档即可完成。

## 核心结构

林超式知识生成器不是固定模板，而是一组材料加工角色。根据材料自然取舍，不要机械填满每一栏。

1. **进入视角**：说明这份材料从什么问题进入，它在整套知识中的位置是什么。
2. **核心抓手**：用一句话锁定最能统摄材料的概念、机制或矛盾，例如“系统论的核心是关系”“工程学的核心是实现”。
3. **核心问题**：把材料转化成可持续追问的问题，而不是保留成章节名。
4. **逻辑递进**：压出材料的展开骨架，说明概念、案例、机制和结论如何一步步推进。
5. **结构化展开**：主体部分按逻辑角色组织，常见角色包括核心定义、现象与影响、机制解释、抽象解决方法、具体实现路径、现实应用。
6. **方法抽象**：只提炼由材料逻辑和案例共同支撑的可迁移方法，不把所有重要概念都升格成方法。
7. **使用方式**：把内容转化为可操作的问题链、判断链或行动链，说明读者以后遇到现实场景时如何调用。

## 加工流程

### 1. 先定材料身份

先判断材料是理论体系、经验案例、方法课程、工具清单、访谈记录、现实复盘，还是混合材料。材料身份不同，正文结构不同：

- 理论体系优先保留定义、机制和边界。
- 方法课程优先抽出核心抓手、逻辑递进和使用方式。
- 案例库优先把案例降级为证据，抽出共同机制。
- 工具清单优先寻找上位问题、生成顺序和约束关系。
- 访谈或转写优先区分事实、经验判断、隐含方法和可复用框架。

### 2. 再找核心抓手

核心抓手不是主题词，而是能让材料重新组织起来的轴心。它通常回答：

- 这份材料真正反复处理的对象是什么。
- 哪个概念能解释最多下游内容。
- 哪个矛盾或机制把分散段落串起来。
- 哪个词可以成为读者后续调用这份笔记的入口。

如果只能写出“本章讲了 A、B、C”，说明还没有找到核心抓手。

### 3. 保护原材料逻辑

压缩不是改写成自己的理论。可以换结构，但不能改掉材料自身的推进关系。

- 保留能支撑核心机制的定义、推理链、案例和边界。
- 删除重复表达，但不删除承担解释功能的细节。
- 案例只有在解释机制、支撑判断或界定边界时保留。
- 没有材料支撑的栏目可以弱化或省略，不为了完整模板虚构内容。

### 4. 把正文写成结构化展开

主体正文优先按逻辑角色组织，而不是按原始目录机械搬运。

常见展开顺序：

`核心定义 -> 现象与影响 -> 机制解释 -> 抽象解决方法 -> 具体实现路径 -> 使用边界`

这个顺序可以调整，但不能退化成概念罗列。每一段都要说明它在材料中的角色：是在定义对象、解释现象、推出机制、给出方法，还是提供应用边界。

### 5. 谨慎做方法抽象

方法抽象只收录能迁移到其他对象上的内容。判断标准是：它能否帮助人诊断问题、拆解结构、识别变量、判断取舍或指导行动。

不要把这些内容强行列为方法：

- 只在原材料内部成立的概念。
- 生活启发、应对手段、训练建议。
- 表达技巧、执行工具、案例结论。
- 尚未形成问题链、判断链或操作闭环的原则。

一个关键方法讲透，比多个方法名并列更有价值。

### 6. 最后落到使用方式

好笔记不能只让人知道“它讲了什么”，还要让人知道“以后怎么用”。使用方式可以写成：

- 一组诊断问题。
- 一条判断链。
- 一个行动流程。
- 一个现实场景中的调用入口。
- 一组边界和反例。

如果读完后仍然不知道遇到现实问题该先看哪一层、问哪几个问题、避开什么误用，说明还没有变成知识生成器。

## 输出形态

### 单章或单篇材料

优先输出：

- 核心抓手
- 核心问题
- 逻辑递进
- 结构化展开
- 使用方式

方法抽象可有可无；只有材料真的支撑可迁移方法时才写。

### 长书、课程或系列材料

优先输出：

- 总框架
- 每一章或每一讲的核心抓手
- 跨章节方法链
- 反复出现的机制和边界
- 长期主笔记的更新入口

不要为每一讲生成平行摘要后停止。长期主笔记要合并进整体框架，并更新总框架和方法链。

### 多来源主笔记

优先输出：

- 应用入口型结构，而不是来源目录。
- 机制名作为正文入口，来源标题只作追溯锚点。
- 共同机制、冲突判断、适用边界和反例。
- 读者遇到现实场景时的调用路径。

## 质量门槛

- **不是摘要堆叠**：能回答“它通过什么结构解决什么问题”，而不只是“它讲了哪些点”。
- **不是工具名展览**：每个工具或方法都必须带来新增解释，不用名词装饰正文。
- **不是过度抽象**：案例和细节只要承担解释、校验或边界功能，就应保留。
- **不是模板填空**：材料不支持的栏目宁可省略，不虚构完整性。
- **不是过程汇报**：最终笔记面向读者和未来调用，不写“本文将整理”“这一部分最有用的是”等自我说明。

## 与模块的配合

- `thinking-analysis.md` 负责判断是否需要读取本文件，以及是否需要先用 Toolbox 选择主工具。
- `note-processing.md` 负责把本文件转化为笔记结构、压缩强度和正文质量门槛。
- `writing-creation.md` 可在文章写作中借用“核心抓手、核心问题、逻辑递进、使用方式”，但不要把文章写成课程笔记。
