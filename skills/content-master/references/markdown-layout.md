# Markdown 排版审阅

## 排版职责

把已经稳定的文字关系转成清楚、克制、美观的 Markdown 阅读界面。排版服从语义层级和真实文体，不改变事实、立意、证据、作者位置和正式效力。

先识别文稿中的真实层级、并列、顺序、引用、对比和补充关系，再选择格式。不能用增加标题、列表、加粗、引用框和表格弥补内容结构不成立。

## 标题

- 一级标题只承担文稿总题；正文从二级标题开始组织主要部分。
- 同级内容使用同一级标题，上下级关系才改变标题级别。
- 标题应标明问题推进、对象或模块功能，不只追求对仗和整齐。
- 简短内容不强拆小标题；标题下面只有一两句且没有独立功能时，考虑合并。
- 不跳过标题层级，也不把加粗句冒充标题。

## 段落与留白

- 每段围绕一个主要作用，事实、解释、判断或转折发生变化时再分段；叙事、随笔中的场景、情绪、节奏、视角与照应同样可以决定段落安排。
- 复杂关系可以使用较长段落；移动阅读可适度缩短，但不能把完整判断切成连续碎句。
- 标题、列表、引用、表格和代码块前后保留空行，确保稳定渲染。
- 连续多个短段、列表或引用造成视觉噪声时，恢复自然段。

## 载体与扫描方式

- 按 writing-creation.md 已确定的载体和注意力预算排版，不把同一版式复制到即时消息、移动端文章、正式报告和长期研究笔记。
- 即时消息、提词稿和移动端扫描内容可以一意一行，三个及以上同轴对象可改成纵向阵型，少量关键数字或结论可单独成段；长篇连续论证保留自然段和必要复句。
- 减少逗号的目标是拆开同一句中的多个认知动作，不是追求短句数量。连续碎句、每个句号都换行或平均段长都会制造新的阅读噪声。

## 列表与嵌套

- 有序列表只表示步骤、优先级、时间或其他明确顺序。
- 无序列表表示并列项目；同一层项目必须回答同一个问题，并保持相近颗粒度。
- 解释、示例和子项必须缩进到所属父项下。更换 `1.`、`-` 或 `*` 不会自动产生正确层级。
- 条目需要连续论证或包含多个段落时，优先改用小标题和正文。
- 不为了凑“三点”“五步”拆分本来可以直接说清的内容。

正确嵌套示例：

```markdown
- 高频模板句
  - “不是……而是……”
  - “这，才是……”
- 机械结构
  - 每节固定三点
  - 每段长度相同
```

## 加粗与斜体

- **加粗**钉住核心判断、关键定义、必要条件和读者必须识别的动作。它是扫描阅读时的语义检索层，不是句子美容。
- 研究笔记、方法说明和以扫描为主的长文，可形成三层阅读路径：标题定位，加粗呈现关键概念或判断，普通段落解释依据。随笔、叙事或以连贯阅读为主的文章不强制这套版式，可以用自然段、节奏与照应组织阅读。
- 在需要概念检索的笔记或说明中，核心概念首次承担定义、推理或后续调用功能时，可加粗准确名称；先服从用户指定样式。检查同层概念是否采用一致标准，不意味着每个术语都要强调。局部排版任务只检查受影响范围，不由一处加粗自动扩张为全文改版。
- 一段通常只保留少量真正重点；整段加粗、逐项加粗会让强调失效。
- 斜体只承担轻微语气或术语区分，中文正文不依赖斜体建立主层级。
- 不用加粗制造金句，也不把所有列表标签都机械加粗。

## 引用

- 引用块用于真实引文、来源材料、原始提问，或需要与正文明确分离的定义和输入。
- 引用应保留必要归属；长引文只摘取当前论证需要的部分。
- 作者自己的结论直接写入正文，不用引用框装饰。
- 引用块之后要说明它与当前判断的关系，不能让引文代替论证。

## 表格

表格适合多项精确映射、同口径比较和重复字段。使用前确认：

- 行列是否共享稳定字段；
- 读者是否需要横向比较；
- 单元格能否保持短而明确；
- 改成正文或列表后是否反而更难理解。

单一路径、简单清单、长段解释和连续论证不用表格。表格中塞入大段文字会同时破坏阅读和移动端显示。

## 链接、代码与图片

- 链接文字说明目标内容，不使用大量“点击这里”。
- 代码块标注正确语言；命令、代码、输出和解释彼此分开。
- 图片只在提供文本无法高效表达的信息时使用，并给出简洁替代文本。
- 本地文件、来源链接和脚注要服务核验与复用，不把正文改成链接清单。

## 文体与版面

- **长篇文章**：用少量稳定标题建立阅读路径，段落长短随论证变化。
- **研究与技术文本**：优先保证口径、公式、代码、表格和来源可核验。
- **公文、纪要、述职和汇报**：排版突出事项、责任、时间、决定与待办，不用自媒体式金句和装饰引用。
- **简短答复**：能够用两三段说清时不增加目录、多级标题或复杂列表。

## 完成检查

- 视觉层级是否与语义层级一致？
- 是否存在标题跳级、空标题或只有一句话的小节？
- 有序列表是否真的有顺序，无序列表是否真的同层？
- 子项是否正确缩进并归属于父项？
- 每处加粗、引用和表格是否承担明确功能？
- 采用扫描阅读版式时，标题与强调能否帮助定位对象、关系与边界？同层强调是否一致？叙事与随笔的连续阅读是否被过多格式打断？
- 段落和留白是否让阅读路径清楚，而没有把文章切碎？
- Markdown 在目标阅读环境中是否能够正确渲染？

发现内容关系本身不成立时，停止增加格式，返回 `writing-creation.md` 的 C 阶段修复结构。
