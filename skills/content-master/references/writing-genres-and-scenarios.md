## 选择文体前确认

- **文本动作**：要记录、解释、评价、建议、请示、决定、部署、复盘还是传播；
- **作者位置**：代表个人、专业岗位、部门、会议还是组织；
- **目标读者**：谁需要理解，谁能决定，谁要执行，谁会受影响；
- **事实基础**：哪些已经核实，哪些只是意见、推断或待核事项；
- **完成标志**：读者看完应形成什么认识、决定或动作；
- **效力来源**：来自事实和论证、作者经验、专业资格、会议程序，还是正式授权。

文体不是版式标签。把报告写成请示会转移决定责任，把请示写成通知会制造越权，把纪要写成宣传稿会破坏事实记录，把公众号套路套在研究文章上会牺牲可信度。

## 公共文章与公众号

公众号是分发场景，不是单一文体。先确定文章是在解释现象、记录体验、分享工具、提炼方法、表达个人经验还是发表评论，再处理平台的注意力、移动阅读和长期作者关系。

### 传播要完成四层任务

1. **看见**：标题准确承诺正文价值，不用虚假冲突、焦虑和过度确定性换点击。
2. **进入**：开头尽快建立真实问题、具体场景、矛盾或阅读理由，不用悬念无限拖延关键信息。
3. **理解**：正文提供事实、关系、判断和边界，节奏不能替代复杂性。
4. **留存或行动**：读者能够记住核心认识、形成判断，或找到可信的下一步；不强制煽动和行动召唤。

标题要让读者看见对象、问题和能够兑现的价值。话题本身存在真实争议时可以呈现张力，不能人为制造敌我。开头可以从场景、冲突、反常识事实或直接判断进入，但应尽快回答“发生了什么、为什么值得看、文章能增加什么认识”。

关键观点处可以使用犀利总结、反问、反差或黑色幽默。它们的作用是压缩判断、暴露矛盾或加强记忆；只有事实稳固、对象明确、符合作者原有语气时才使用。不要为了“网感”攻击人物、替代论证或让每节都有一句毒舌金句。

结尾根据文章任务选择清楚结论、回扣开头、保留余味、提出未决问题或给出行动入口。没有必要固定加“希望对你有帮助”、互动问题、情绪拔高或暴击收尾。

### 账号关系决定长期写法

- **个人作者型**依靠持续可识别的判断、经历和语言；重点是经验如何形成公共认识，避免表演人设和虚构日常。
- **专业研究型**依靠事实质量、解释能力和长期可信度；重点是口径、机制、反方和跟踪框架，避免资料摘要和抢热点式定论。
- **行业业务型**依靠一线经验、案例和可迁移方法；重点是决策点、成本、条件和结果，避免黑话和只报成功。
- **工具产品型**依靠真实使用价值和复现能力；重点是场景、上手、效果、限制、数据与权限，避免说明书和软广。
- **机构品牌型**依靠正式身份和组织信用；重点是授权口径、公共信息、服务入口和纠错机制，避免把机构自我评价写成事实。
- **热点评论型**依靠反应速度和解释增量；重点是已确认事实、独特关系、价值标准和更新机制，避免把早期消息写成结论。

账号类型只决定长期关系和质量重心，不直接决定单篇结构。优先用用户提供的账号样本和既有文章归纳真实风格，不假定所有公众号都应强冲突、强情绪、短段落或固定召唤。

### 五种常见文章原型

原型是构思候选，不是固定模板。材料同时覆盖多种原型时，先确定一条主骨架，再借用其他原型的局部功能。

#### 调查实验型

成立基础是作者确实亲自测试了产品、流程或现象。主推进通常为：起因 → 行动 → 发现 → 判断或反转 → 适用条件。过程要有真实动作、反馈和认识变化，让读者能够跟着走一遍；不能补造过程，也不能为了戏剧性强行设置反转。

#### 产品体验型

围绕真实使用场景展开：为什么使用 → 怎样上手 → 哪些亮点和槽点 → 与什么比较 → 最终判断。好恶要有明确标准，不能只复述功能，也不能把一次个人体验直接扩大成普遍结论。

#### 现象解读型

从可核验现象进入，说明它为什么值得注意，再追到机制、影响和边界。可以开头给出工作判断，但证据和机制必须承担真正展开；不能只有观点，也不能为了层层剥开而故意拖延已经确定的事实。

#### 工具分享型

从一个真实任务或卡点进入，说明工具怎样改变具体动作、依赖哪些数据和权限、效果如何、谁适合以及谁不适合。工具是解决问题的载体，不是文章中心；不能写成“有个好东西快来用”，也不能隐藏成本、失败点和内部资源依赖。

#### 方法论分享型

适合作者已经形成较成熟的经验、框架或判断。正文要说明它解决什么问题、为什么有效、怎样实施、学习曲线和误区是什么、在哪些条件下失效。每节可以落到判断或行动，但不必强行制造统一步骤；经验来源和适用边界比谦逊套话更能避免导师腔。

### 热点、事实和纠错责任

热点提供共同背景和传播窗口，也带来事实未定、情绪过热和信息竞争。快速写作至少区分：

- 已经确认的事实；
- 基于现有信息的推断；
- 作者采用的价值评价。

新意可以来自新事实、新关系、新对象位置、新解释或新路径，不必故意反常识。文章发布后若事实变化，应保留更新、更正或撤回错误信息的能力；一次传播量不能高于长期解释信用。

## 随笔、个人经验、评论与杂文

### 个人经验怎样进入公共问题

私人经历获得公共价值，需要完成：

> 还原具体经历 → 识别其中的关系或冲突 → 说明对更广泛问题的启发与边界

只停留在经历是记录；跳过经历直接上升到大道理，会失去真实基础。第一人称可以承担证据位置、认识变化和责任，但不能把个人感受自动升级成普遍规律。

### 随笔

随笔允许结构、联想、情感和语言更自由，但始终需要一个持续的感受或判断中心。可检查三种质量：

- **有料**：存在具体经历、细节、对象和观察；
- **有趣**：语言、场景和视角能够激活注意；
- **有度**：情感、议论和推断不超出经验能够支撑的范围。

记忆会重构经历，情绪会放大细节。涉及真实人物时，区分观察到的行为、自己的感受和对他人动机的推测。哲理最好从具体关系自然长出，不要让人物沦为证明作者正确的符号。

### 评论

评论围绕已经发生的公共事实形成判断。先稳定共同事实，再定位争议关系、判断依据和价值标准，处理最强反方，最后说明影响、边界或行动。快评要标记事实、推断和评价；观点新不等于故意与所有人相反。

### 杂文

杂文借具体矛盾、反差或荒诞揭示更深机制，常用短结构：具体现象 → 表里反差 → 机制解释 → 有限而明确的判断。修辞越锋利，越要核准批评对象和事实边界。批评行为、机制和后果，避免用有限事实完成对人格或群体的整体定性。

## 研究、技术与方法文章

### 研究或分析文章

先明确研究对象、问题、口径和证据范围，再组织概念、事实、机制或比较。正文必须说明证据怎样支持结论、有哪些替代解释、结论适用到哪里。数据、案例、相关性和因果不能混用，引用数量不能替代当前论证。

常见主路径包括：

- 问题 → 概念与口径 → 证据 → 机制 → 结论与限制；
- 统一比较口径 → 差异 → 原因 → 取舍；
- 现状 → 演化 → 转折 → 风险与跟踪指标。

### 技术说明或教程

目标是让读者正确理解并完成一个可复现动作。至少交代前置条件、输入输出、最小可用路径、关键参数、失败信号、验证方法和限制。代码或步骤不是自解释内容；需要说明它与业务动作、数据口径和结果验证怎样对应，并标明版本、权限和环境依赖。

### 方法论文章

方法论文章把经验转成可迁移的判断和动作。它必须回答：解决什么问题，关键变量和动作是什么，为什么有效，依赖哪些条件，失败时怎样识别。个人成功不能直接升级为规律；步骤要说明理由，方法要保留成本、学习曲线和退出边界。

#### 隐藏门槛型方法文章

当读者以为拿到工具、代码或数据就能开始，而真正门槛在格式、单位、权限、入口、映射和业务口径时，使用这类结构：

1. 还原一个具体卡点，让读者看见错误怎样真实发生；
2. 给出全局风险地图，让读者先判断自己卡在哪个关口；
3. 按关口解释“原始状态 → 直接使用的后果 → 正确处理 → 为什么”；
4. 交代可复用资源及其边界；
5. 说明本文解决到哪里，后续问题是什么。

工具、GitHub、demo 或数据入口如果是读者马上要使用的资源，应在开头或首次相关位置尽早交代；若会打断问题建立，则放到第一个真正需要它的段落。正文重点仍然是业务口径、判断逻辑、错误后果和处理原因，不写成命令行手册，也不单设只服务作者意图的“代码放在哪里”标题。

风险地图可以使用表格，但只有关口、原始状态、直接使用后果和正确处理等字段需要反复横向比较时才使用；每格只放短判断，关键原因在正文展开。链接必须区分公开代码、demo、数据、密钥、商业接口和内部资产，不能让读者误以为所有内容都可直接获得。

## 公文与组织文本的共同效力

组织文本同时取得三种效力：

- **授权效力**：谁以什么身份写，是否有权作出判断、承诺或要求；
- **内容效力**：事实、政策、判断和措施是否可靠；
- **执行效力**：接收者是否知道谁在何时完成什么、达到什么标准并怎样反馈。

组织文本承接一条现实链：

> 现实输入 → 政策与授权校验 → 组织判断 → 文种选择 → 责任和行动配置 → 正式发布 → 执行反馈

形式权威不能替代事实与可行性，内容正确也不能绕过授权和程序。正式格式、法定文种、法规、政策口径和机构模板可能变化；需要正式签发时必须核对用户提供的现行制度和权威来源，本文件只保存稳定的功能结构。

组织文本通常同时面对上级和实际共同体，因此要接受三向检验：熟悉工作事实的人能够确认材料真实，拥有决策权的人能够看见行动价值与取舍，执行者和受影响对象能够理解责任、成本与后果。结果导向不能把程序、公平、合规、安全和长期信任当成可省略的过程；它们本身就是组织结果的一部分。

## 决议、意见、请示、报告、通知、方案与纪要

### 决议

决议把会议已经形成的重大决定固定为正式成果。起草稿只有经过相应程序后才取得效力。正文应准确呈现决策对象、基本判断、主要决定和执行方向；起草者可以提高概括质量，不能替会议补造共识或把少数意见写成集体决定。

### 意见

意见为重要工作配置原则和实施空间。刚性部分说明必须遵守什么，弹性部分说明在什么条件下允许调整、由谁批准。使用“原则上”“一般”等词时必须给出例外条件和责任接口，不能用模糊替代灵活。

### 请示

请示向有权主体请求决定或授权。先说需要决定什么、为什么现在决定，再提供事实依据、可选方案、风险和建议。决策者应能够清楚批准、否决、选择或要求补充。不得用倾向性材料逼迫批准，也不得把已擅自执行的事项包装成事前请示。

### 报告

报告是纵向信息接口，向上级提供真实情况、进展、问题、判断和必要建议。问题性报告要完成：确认问题 → 判断性质 → 提供典型事实 → 分析原因与危害 → 提出处置建议。报告问题不等于上交责任；提出建议也不能筛掉风险和不确定性。

### 通知

通知把事项或要求转成可执行动作。接收者必须知道依据、对象、事项、动作、时限、标准、例外和反馈方式。与行动无关的背景尽量压缩；不要为了减少发文数量捆绑无关事项，也不能在没有授权时发布刚性要求。

### 方案

方案把目标转成可选择、可执行和可评估的行动设计。至少说明现状、路径、资源、责任、进度、风险、替代方案、退出条件和反馈。授权者应能比较取舍，执行者应能据此行动；不能只有理想目标和步骤，也不能把唯一方案伪装成选择。

### 会议纪要

纪要固定会议事实、主要意见、正式决定和责任结构。要区分讨论过程、已形成决定、保留异议和待核事项；议定事项尽量写清责任主体、任务、期限、资源条件和继续请示的问题。主持总结不自动等于决定，未议定内容不能由整理者补进纪要。

若用户要忠实保留每个人说了什么，任务更接近记录型笔记；若要形成正式可执行纪要，则必须确认授权、决定状态、责任人和复核节点。

## 总结、调研报告与领导讲话

### 总结

总结把结果、原因、经验、问题和改进转成组织记忆。目标完成到什么程度、结果因何产生、哪些机制可复制、哪些来自环境或运气、下一轮怎样改，都要能够对应。不要把总结写成宣传，也不要把偶然成功包装成普遍经验。

### 调研报告

调研报告把多位置现实转换成决策依据。调研和写作形成循环：问题假设指导调查，现场发现修正假设，阶段性写作暴露证据缺口，补充调查再完善结论。带着问题有利于聚焦，带着既定结论找例证会把调研变成认证。

根据决策问题选择重点：

- **情况类**说明当前真实状态、比较口径和未知；
- **问题类**让问题链、因果链和对策链对应；
- **经验类**提炼关键动作、资源条件、结果和失效边界；
- **研究类**针对新问题形成有证据和可行性的新判断；
- **历史类**多源互证并还原语境，避免孤证和现实投射。

分类可以组合，结构始终服从决策问题。建议必须说明怎样验证、资源从哪里来以及可能造成什么副作用。

### 领导讲话

讲话稿把发言人的位置、组织意图和听众处境翻译成共同认识与行动方向。起草前同时吃透真实情况、上位政策与约束、领导真正准备推动和承担的意图；三者不能互相替代。

讲话的思想性、针对性和指导性构成一条链：思想性给出判断，针对性决定怎样面向当前听众翻译，指导性把认识转成目标、动作和责任。所谓高度来自发言位置能够统筹局部与整体、当前与长期，并有事实和理论支撑；不来自宏大语气。

工作讲话可以沿：事实与成效 → 形势判断 → 少数重点 → 任务和资源 → 风险边界 → 立即行动。篇幅由任务决定，应急、专项和即席讲话尤其要短而明确。不能替领导虚构经历、感情、数字、政策口径和承诺。

## 述职、工作汇报与发言

### 职场表达适配器

这些适配器帮助作者在短时间、有限页面或明确职场场景中压缩和排序已经成立的内容。它们是表达单元，不是全文必须照抄的目录；同一个单元选择一个主适配器，不能为显得完整把多个公式层层叠加。任何公式都不能替代共同写作底座中的任务效力、事实、证据、推理、边界、贡献归因和授权。

- **讲解型路径**：Why → What → How 适合先建立意义，再解释对象和用法。顺序服从读者任务；决策者时间有限时可以改成“结论或对象 → 原因 → 行动”，不机械从 Why 开始。
- **观点支撑单元**：Point → Reason → Example / Data。Point 给出一个可承担的判断，Reason 说明理由或机制，Example 和 Data 是证据类型，按解释效率择一或组合，不要求每次两者俱全。内部仍用“主张 → 证据 → 推理 → 边界”验收；结论会推动决定时再补影响、建议或下一步。
- **个人视角单元（4I）**：I see → I feel → I think → I will，分别对应可观察事实、本人真实感受、个人判断和本人能够承担的行动。材料没有提供感受时不得代写；承诺必须在作者权限和能力范围内。
- **团队视角单元（4F）**：用户材料或组织明确采用时，按其定义组织 Facts、Feeling、Finding、Feature。事实、团队感受和共同发现必须分开；第四项的具体含义按课件或组织口径执行，未核对时不自行猜测或对外宣称为统一标准。任务需要行动接口时，另补责任、时间和验证方式。
- **单项成果单元（STARs）**：Situation → Task → Action → Result → Suggestions / Solution，用于一个项目、成果或典型案例。Result 必须可核验，Action 要区分本人、团队与协作方贡献，建议回应尚未解决的问题。整份述职仍由职责与责任链统摄，不能把每项工作都机械写成一套 STAR。
- **复盘行动单元**：Keep → Improve → Start → Stop，用于在事实、结果和问题已经分析之后形成行动组合。四类不必凑齐；每项写清依据、责任、时间和验证方式。若需对外标注课程模型名称，先核对课件原称。

排比只在三个及以上同轴事实、动作或承诺需要形成记忆节奏时使用。去掉重复句式后没有新增信息的排比应删除；排比不能替代论证，也不能用来制造公文感。

### 述职

述职完成个人职责、行动、结果和责任的归因审计，不是工作日志或成绩包装。稳定链条是：

> 职责要求 → 面临问题 → 本人判断与动作 → 调动的资源和协作 → 可核验结果 → 未解决问题 → 改进责任

筛选事项时必须问：

- 这件事是否属于岗位关键责任；
- 若没有本人介入，过程或结果会发生什么变化；
- 本人的贡献是判断、配置资源、解决障碍、承担风险，还是仅参与执行；
- 结果是否能够被外部证据验证；
- 它是否反映可迁移能力，而非一次偶然事件。

数字要说明口径、时间、基线、比较对象和归因范围。工作量不能自动证明价值，加班、发文和会议次数也可能暴露流程低效。区分本人独立完成、主导团队完成、参与完成和由下属或协作单位完成；负责人可以承担领导责任，不能把所有产出写成个人劳动。

问题部分要写具体表现、影响、本人责任和可改变原因，改进措施对应动作、期限和验证方式。不能用“学习不够、创新不足”敷衍，也不能为了仪式效果虚构自我批评。

### 工作汇报

汇报的价值是降低决策者获取事实、理解问题和比较方案的成本。决策型汇报通常回答：

1. 需要决定什么；
2. 为什么现在决定，不行动有什么后果；
3. 关键事实、分歧和不确定性是什么；
4. 有哪些方案，各自成本、收益、风险、资源和可逆性如何；
5. 建议选择什么，需要什么授权。

如果只需知悉情况，不制造虚假决策请求；如果确实需要选择，不把建议埋在背景里。事实、专业判断和领导决定必须分开。使用“问题—措施—成效—建议”时，重点不是四段齐全，而是每项措施回应哪个问题、产生什么结果、剩余缺口为什么需要新决定。

即席汇报使用最小问题地图：我的判断 → 两三项关键事实 → 对当前方案的影响 → 下一步建议。时间越短，越要前置新增信息和决策影响，把背景移后或放入附件。

### 发言

发言从自身位置为共同议题提供新增事实、经验、判断或问题，不是缩短版讲话。先连接现场，再给一个核心判断，用两三项关键依据支撑，最后形成有增量的建议或疑问。未经授权不替其他部门、群体或组织表态。

学习发言要连接“新信息 → 原有认识 → 现实问题 → 验证或应用”，不能只复述课程，也不能让理论只充当权威背书。检视发言要形成“具体表现 → 影响 → 可控原因 → 责任 → 改进动作 → 验证节点”，不能把所有问题归为思想认识不足，也不能为了显得深刻无限上纲。

## 场景选择的最后校验

- 文体是否与真正需要完成的动作一致；
- 作者是否拥有相应事实、位置和授权；
- 读者能否区分事实、意见、建议、决定和执行要求；
- 关键内容是否回答了该文体真正必须回答的问题，而不是机械填满统一栏目；
- 场景技法是否改善了读者路径，还是反过来支配材料；
- 是否存在现行格式、政策或机构口径需要实时核验；
- 文本发布后，谁负责执行、反馈、纠错或更新。
