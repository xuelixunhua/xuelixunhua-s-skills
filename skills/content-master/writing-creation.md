# 公众号创作 - 融合版方法论

## 核心定位

这个模块处理的不是“写点内容”，而是把素材、想法、笔记、研究资料、真实经历，加工成适合公众号传播的深度长文。

目标不是只把文章写长，而是同时做到四件事：
- 帮用户判断，这个题值不值得写
- 帮用户找到，这篇文章该按什么原型来写
- 帮用户把观点、案例、知识和情绪组织成一篇完整作品
- 帮用户把 AI 味压下去，把“活人感”和作者判断力提上来

## 核心特质

基于用户画像定制：
- 深度思考和逻辑分析
- 跨领域知识整合
- 实践导向，可执行、可验证、可复用
- 结构清晰，但不写成讲义

## 读者定位

目标读者：聪明、有选择、很忙的人
- 结构清晰，重点明确
- 信息密度高，避免废话
- 深度思考，不是泛泛而谈
- 默认读者很懒，也默认作者应该很懒：能让读者自动补上的内容，不要替他完整展开；每多解释一层，都要确认它真的降低理解成本。

## 与思维分析的交汇原则

公众号写作不是和思维分析并列排队的关系，而是默认允许随时借用思维分析来补判断力。

重点记住：
- **写作模块负责成文与传播**
- **思维分析模块负责补本质、补机制、补取舍、补判断**

只要文章出现以下情况，就不要硬写，先插入 [thinking-analysis.md](thinking-analysis.md)：
- 选题似乎能写，但说不清为什么值得写
- 有材料、有故事，但没有一句能钉住全文的核心判断
- 结构能列出来，但段落之间只是并列堆砌，没有推进
- 文章读起来顺，却像“正确废话”或“高级 AI 摘要”
- 需要回应反方、解释机制、做取舍判断，但草稿里没有这一层

## 创作流程

### 第 0 步：先判断任务模式

先识别用户真正要的是什么：

| 模式 | 用户常见说法 | 主要交付物 |
|------|--------------|------------|
| 选题诊断 | “这个题能不能写”“值不值得写” | 选题判断 + 角度建议 |
| 提纲设计 | “先帮我搭结构”“给我大纲” | 标题方向 + 提纲 |
| 成稿起草 | “帮我写一篇” | 完整初稿 |
| 改写增强 | “这篇太 AI 了”“帮我改顺” | 重写稿 + 修改说明 |
| 草稿质检 | “检查下问题” | 质检报告 + 修复建议 |
| 标题排版 | “给我标题”“排一下版” | 标题组 / 排版稿 |

同时判断主要写作目标是传播、专业表达、个人表达还是实用交付。不是所有公开文章都以“爆款”为目标；标题、开头、篇幅、案例密度和结尾方式应服从本次目标。

如果用户说得笼统，优先根据上下文直接判断；只有当缺失信息会显著影响成稿质量时，才补问最少的问题。

### 第 0.5 步：判断是否先插入思维分析

在正式进入写作流程前，先快速判断这是不是一个“必须先想清楚再写”的题。

优先插入思维分析的情形：
- 用户还在摇摆“这个题到底值不值得写”
- 用户有很多素材，但没有明确主判断
- 用户想写的是现象、趋势、方法论、经验总结，这类题天然需要机制解释
- 用户已经写了草稿，但你判断问题不是文风，而是判断链条偏弱

这一步不是额外流程负担，而是为了避免后面在错误主线上越写越多。

### 第一步：材料充分性检查（按需沟通）

优先从用户现有材料和上下文里提取，不要重复盘问。主题、核心判断、关键材料、目标读者和写作目标已经足够时，直接推进。

只有缺失信息会改变文章立场、事实可信度、作者声音或整体方向时，才补问最少的问题。通常只问 1-3 个高信息量问题；如果用户希望先看初稿，可以声明必要假设后继续写。

需要补问时，优先检查：
- **核心主题**：到底想写什么
- **个人角度**：你在这个话题上的独特经历、观察或判断是什么
- **目标效果**：希望读者看完有什么感受或行动
- **争议程度**：准备写得多犀利，温和、适中还是犀利
- **未表达想法**：有什么想说但还没说清楚的

如果素材明显不足，优先补三件事：
1. 这篇文章最想讲清楚的 1 个核心判断是什么
2. 有没有你自己的经历、观察、案例，哪怕只有一两个细节
3. 你希望这篇文章更偏叙事、分析，还是方法论

### 第二步：选题诊断

在动笔前，先判断题目值不值得写。

#### 2.1 选题交集模型

一个值得写的题，至少同时满足其中两项，最好三项都满足：
- **专业度**：作者在这个题上有认知积累、实践经验或独特观察
- **读者兴趣**：对目标读者有现实帮助、认知增量或情绪共鸣
- **时间节点**：当下有热点、争议、窗口期或现实语境支撑

#### 2.2 HKR 质检法

- **H（Hook）**：开头够吸引人吗
- **K（Knowledge）**：有新信息、新框架或独特观点吗
- **R（Resonance）**：能产生共鸣吗

输出时要给明确判断：
- 值得写，建议直接进入某个角度
- 值得写，但需要补一个真实案例或明确主线
- 题目偏弱，建议换角度或换切口

如果发现选题判断卡在“为什么这个题成立”“核心张力在哪里”“读者为什么会在意”，转入思维分析处理以下问题：
- 这篇文章真正想判断什么
- 这个判断对应的现实矛盾是什么
- 读者会因为哪个变量或代价对它产生兴趣

### 第三步：明确 AI 和人的边界

#### AI 擅长做的

- 梳理结构和主线
- 补背景知识、历史参照、类比候选
- 扩写已经明确的观点
- 找支持和反对论据
- 对草稿做节奏、逻辑、表达层面的修订

#### 不能替代人的

- 第一手经历和真实观察
- 作者真正相信的核心角度
- 体感式情绪表达
- 对具体人物和具体处境的同理心转换

不要替用户捏造“我昨天如何如何”“我当时特别震撼”之类的真实经验。

### 第四步：选择文章原型

先判断按哪种原型写，再定结构。详细说明见 `references/wechat-writing-archetypes.md`。

常用原型：
- **调查实验型**：亲自做一件事，然后报告发现
- **产品体验型**：真实体验一个产品或流程，带读者一起走一遍
- **现象解读型**：从一个现象切入，层层分析到更深的判断
- **工具分享型**：分享工具或方法，但必须用真实场景和故事包裹
- **方法论分享型**：系统讲经验，但每一节都必须落到可执行动作

如果素材是混合型，可以主原型 + 辅助原型组合，但必须有一个主骨架。

### 第五步：架构设计

基于沟通结果提供：
- 按需提供 1-3 个标题方向；用户只要正文或已有标题时，不强制补标题
- 文章原型判断
- 故事化或论述文结构大纲
- 关键论点和个人化论据
- 必要时再设计互动点、记忆句和结尾收法，不把它们当成固定栏目

结构设计时优先考虑这些骨架：
- 现象切口 -> 背后机制 -> 现实影响 -> 观点升华
- 具体事件 -> 层层发现 -> 判断变化 -> 回扣主题
- 个人困境 -> 方法拆解 -> 实操建议 -> 代价与限制
- 工具体验 -> 创意案例 -> 效果展示 -> 更深理解
- 具体卡点 -> 避坑清单总览 -> 逐关拆解 -> 工具入口 -> 下一步承接

如果大纲只能列出“几个并列观点”，但无法解释它们为什么这样排序、靠什么推进，就调用思维分析先补三件事：
1. 这篇文章的一句话核心判断
2. 支撑这个判断的机制链条
3. 最值得回应的反方或限制条件

写作结构的强弱，很多时候不是文笔问题，而是分析层没有把主线钉牢。

### 第六步：内容创作

#### 写作核心原则（按重要性排序）

**1. 逻辑架构性强**
- 清晰的推进结构
- 每段有明确功能和中心论点
- 论据充分，使用数据、案例、类比等多种论证方式
- 逻辑链条完整，前后呼应
- 故事化表达时，避免论文式宏大叙事

**2. 深度和专业性**
- 论证尽量线性递进，减少大跨步跳转
- 挖掘表面现象背后的深层原因
- 提供独特的观察角度和见解
- 补充用户可能遗漏但想表达的观点
- 适当预设反对意见并回应

**3. 传播性（按任务目标启用）**
- 标题先准确传达对象和价值；话题本身存在争议时再使用争议性，不人为制造冲突
- 开头尽快让读者看见真实问题、具体场景或核心张力
- 传播型文章强调讨论空间，专业型文章强调可信度，个人表达强调真诚，实用文章强调可操作性
- 结尾根据文章目标选择回扣、余味、行动入口或明确结论，不强制行动召唤

**4. 活人感优先**
- 用“我”的视角连接真实经历和公共议题
- 真诚表达，承认局限和不完美
- 具体化，优先时间、地点、动作、数字、感受
- 避免 AI 式完美客观

**5. 风格模块化（适度使用）**
- **[毒舌金句模块]**：在关键观点处插入犀利总结
- **[灵魂反问模块]**：在关键节点加入读者互动
- **[暴击收尾模块]**：用黑色幽默或反差收尾

这些模块只在需要时使用，不要机械铺满全文。

**6. 互联网风格**
- 语言简洁有力，避免冗余
- 允许自然口语感，但不能为了“网感”牺牲清晰度
- 排版清晰，平衡长段落与必要的列表、表格、留白

**7. 懒惰读写原则**
- 正常人写作会偷懒：能一句说完的，不拆成三段；能靠读者常识补齐的，不做完整教学。
- 读者也会偷懒：标题、加粗、列表和短段落要帮助跳读，而不是展示作者把问题拆得多完整。
- 简单工具文尤其要警惕“过度解释”：场景已经说明白时，不要再补背景、意义、价值、边界、总结五连。
- 每个小标题都要省读者时间；如果小标题只是把简单动作拆得更碎，就删掉或并入上一节。
- 交付前做一次“懒人删减”：删掉读者已懂、上下文已暗示、只是在证明自己完整的句子。

### 第七步：改写增强

先判断 AI 味来自哪一层：

- **表达层问题**：模板句、节奏整齐、重复解释、抽象词过密或局部生硬，直接使用 AI 味排查和改写技法。
- **判断层问题**：核心观点空泛、机制断裂、证据不足、没有取舍或边界，先进入思维分析，再回来改写。

遇到草稿平、硬、假、像 AI 时，优先使用这些技法：
- 扣主线句
- 知识顺手掏
- 人物画像
- 对立面承认
- 回环呼应
- 反向论证
- 逐一展示

详见：
- `references/live-voice-techniques.md`
- `references/rewrite-examples.md`

但要注意：很多“AI 味”不是措辞问题，而是判断力问题。

如果草稿的问题是：
- 句子都对，但没有作者自己的判断
- 段落都有功能，但没有更深一层的原因和机制
- 好像在分析，但其实只是在换说法重复常识

先不要急着做语言润色，而要先调用思维分析，把以下几层补齐：
1. 作者到底相信什么
2. 这个判断是如何成立的
3. 它成立的边界和代价是什么

然后再回到改写技法，文章才会真的从“像 AI”变成“像一个人在认真判断”。

## 质量检查与 AI 味识别

### 第一层：HKR 快检

- **H（Hook）**：开头够吸引人吗
- **K（Knowledge）**：有新信息或独特观点吗
- **R（Resonance）**：能产生共鸣吗

### 第二层：四层质检

#### L1 硬性问题
- 套话和空话过多
- 工具名、场景名、对象名过泛
- 假设性例子冒充真实经历
- 标签式结尾
- 句式重复、结构重复、信息重复
- 简单问题被拆成过多层级，看起来完整，读起来费劲

#### L2 节奏与口语感
- 开头是不是具体切口
- 长短句是否有变化
- 有没有读起来像报告的段落
- 有没有自然的转场和停顿
- 有没有不必要的僵硬分点

#### L3 内容质量
- 核心判断是否有支撑
- 知识点是不是自然嵌入
- 有没有更深一层的原因和机制
- 有没有读者处境和反方视角
- 原型写法是否跑偏

#### L4 活人感终审
- 这像不像一个真人在认真表达
- 有没有作者自己的判断
- 有没有体温，而不只是信息
- 哪一段最像 AI，如果有，为什么

### 典型 AI 味特征（必须避免）

主流程只保留四类高风险信号：

1. **判断空心**：句子都正确，但没有作者真正承担的判断、证据、边界和代价。
2. **结构过度完整**：简单问题被拆成背景、定义、原因、流程、边界和总结，形式比内容更重。
3. **表达模板化**：固定对照句、整齐分点、重复强调、抽象词和模式化标点密集出现。
4. **真实感伪造**：虚构经历、情绪、人物故事或第一人称，用表演替代事实和判断。

只有在改稿、质检或 AI 味明显时，才读取 `references/anti-ai-smell.md` 的完整排查清单；普通成稿不必逐条执行所有检查。

### 避免方法

- **真诚 > 技巧**
- **个人化 > 标准化**
- **深度 > 广度**
- **省力 > 完整**：在不损失核心判断的前提下，优先让文章更短、更直接、更像人会写出来的样子
- **如果要求冲突，优先保证活人感和真诚**
- **正面推进 > 否定转折**：能直接说清楚的判断，不用“不是……而是……”绕一圈。交付前检索高频模板句，密集出现时必须重写。

更详细的排查清单见 `references/anti-ai-smell.md`。

## 辅助功能

### 取标题
- 吸引眼球，传达价值
- 争议性加好奇心
- 避免标题党，但要有记忆点

### 检查草稿
- 评估爆款潜力
- 识别 AI 味
- 输出优化建议

### 排版优化
- 提升阅读体验
- 结构清晰，重点明确
- 平衡文字段落和列表、表格、留白
- Markdown 排版不是美化，而是把文章的理解路径显性化；不要只用标题分层，要让不同元素承担不同阅读功能：

| 元素 | 主要功能 | 使用判断 |
|------|----------|----------|
| 标题 | 标出推进阶段 | 读者扫标题就能看到文章如何拆问题 |
| 加粗 | 钉住核心判断 | 用在结论句、反共识句、读者必须记住的句子 |
| 表格 | 压缩复杂框架 | 用于层级、对比、映射关系，不要把长段落硬塞进表格 |
| 图片/截图 | 让门槛或证据可见 | 截图要服务论点，比如界面复杂、变量繁多、操作路径真实存在 |
| 链接 | 提供可操作入口 | 涉及网页、工具、数据源时优先用 Markdown 内链，而不是裸 URL |
| 代码块 | 展示可复用动作 | 代码前要说明它和前文手动步骤的对应关系，避免孤立展示代码 |

## 完成与停止条件

满足以下条件后即可交付，不继续机械增加章节或传播组件：

1. 核心判断清楚，并有真实材料、经验或可信证据支撑。
2. 段落之间存在推进关系，不是并列观点堆叠。
3. 文章目标、目标读者和作者声音彼此一致。
4. 重要边界、代价或不确定性已经交代。
5. 没有虚构经历，也没有明显模板句、重复解释和过度拆解。

## 核心技能

- 深度思考和逻辑分析能力
- 热点敏感度和争议话题把控能力
- 情感共鸣和读者心理洞察能力
- 金句创作和幽默表达能力
- 各领域知识整合和类比能力
- 公众号排版和阅读体验优化能力

## 注意事项

- **材料充分时直接推进，只有方向性信息缺失时才补问**
- **优先增强用户表达，不要模仿他人身份**
- **必须区分真实经历和 AI 补充内容**
- **一个点讲透，强于十个点堆砌**
- **如果要求冲突，优先保真、可信和活人感**
- **拒绝 AI 味**
