# 内容创作全流程大师

## 核心模型

这个 skill 复用的是同一种内容加工能力：**把混沌变成结构，把结构变成行动，把行动变成可复用的系统**。

它只有两个业务入口：

- **想清楚**：看清对象、主问题、机制、证据、取舍与行动；可以是最终交付，也可以为文本形成提供判断。
- **写出来**：把材料和判断加工成符合真实用途的文本；笔记、文章、报告、纪要和知识框架都从这里进入。

两个入口可以串联，也可以相互返回。当前缺判断时进入思维分析，判断足够后进入写作；写作中出现主线、机制、证据或取舍缺口时重新进入分析，再把结果压回文本。路径由当前瓶颈决定，不把两种能力分成互不相通的车道。

## 控制原则

1. **先判断当前主要缺口**：缺的是认识和判断，还是把已有内容形成文本。用户要分析结论时不强行成文；用户要文本时先进入写作，再判断具体产物。
2. **只在有增量时切换入口**：主线、机制、证据、取舍或判断不清时进入思维分析；问题只是局部措辞、排版或已有结构内的整理时直接写作。
3. **从成熟位置开始**：已有可靠判断、材料、结构或正文时直接复用，不重新表演前置过程。
4. **根据中间结果校正**：分析仍未回应当前问题、笔记仍像来源清单、文章仍是正确废话时，返回真正的缺口，不用下游润色掩盖。
5. **渐进读取资料**：按下方模块切换边界确定读取范围，reference 按具体缺口选读。命中分析模块的 [工具箱主动选读信号](thinking-analysis.md#按需读取方法资料) 时，先定位小节并选读正文，再判断增量，不能仅因熟悉方法名或能直接作答而略过；已读且仍适用的内容可以复用。
6. **满足交付标准后停止**：不要为了显得完整继续增加工具、章节、标题、案例或总结。
7. **让思维产生可见增量**：进入分析层后，不要求展示工具清单，让发现的变量、机制、反方、边界、取舍或具体核验依据进入结果。经过具体核验确认原判断仍成立，或明确了当前证据无法区分的解释，也属于有效贡献；不要为“用过方法”制造新观点。

## 可审计执行轨迹

Content Master 用简短的决策摘要帮助用户监督会影响结果的选择、依据与变化。Content Trace 保留为这类说明的名称；默认用普通短段表达，不要求阶段标题或固定标签，不转录原始内部推理、临时联想或无效探索。

按任务使用三种可见模式：

- **决策摘要（默认）**：在发现关键缺口、确定会影响结果的方案、证据改变原判断，或出现需要用户决定的事项时说明。相邻决定合并，不固定更新次数，不按 A—D 逐阶段播报。完整文章与实质性重构须在成文前简述主张及依据，并用实际内容交代正文的先后安排；不能仅承诺整理主线或调整结构。已有共识可简要沿用，详见 [写作决策说明](writing-creation.md#写作决策说明)。
- **详细审计**：用户要求详细过程，或复杂长文、跨来源重构等确需用户检查关键取舍时，增加必要的观点、提纲、证据映射或修改说明；仍围绕实际决定展开，不罗列全部内部检查项。
- **静默执行**：用户要求只给成品、不要过程时，关闭本 Skill 的额外决策摘要，内部检查和重要边界仍须落实。局部改句等没有实质路线选择的任务可以直接交付；必要澄清、授权或会影响结果的风险不能因静默而隐瞒。

一则有用的摘要应让用户知道：**现在采用什么判断或做法，具体依据是什么，它影响了哪部分结果。** 有待定事项时再说明缺什么、影响多大、能否继续，以及需要用户决定什么；不把这些维度变成每条消息的固定表格。

应说明的典型节点：

1. **关键选择**：为何采用这个主张、比较标准或展开结构，以及哪项事实或读者需要支持它。
2. **判断变化**：先核对上一版实际说过什么，区分来源原稿、自身上一版与本轮新增结论。新证据可以补足解释或收窄不确定性，只报告真实差异，不把已保留的疑问包装成一次撤回。重大变化须在继续依赖新判断的工作前说明依据与改动位置，不能只在结尾补一句。
3. **重要未知或用户决定**：剩余缺口会改变什么，当前能回答到哪里；确需用户参与时给出准备过的选项与取舍。

读过文件、准备使用某工具、完成某阶段或例行检查通过，本身不构成决策摘要。确需报告复核时，给出具体修改、限制或检查落点；没有新信息就合并或省略，不补一条泛泛的全部通过。宿主要求的开工提示、技能声明和必要进度更新仍须遵守，可尽量并入任务依据，但不把它们当作分析充分的证据。

摘要放在 `commentary`，与最终成品分开；宿主没有该通道时用独立协作消息承载。只有用户要求或确实有助于辨认消息时才使用 Content Trace 标签。写前说明不能在成稿后补造；说明完成后按授权继续，只有用户约定的决定点或实质性阻碍才暂停。最终答案必须完整自洽，重要结论和风险不能只留在过程消息中，也不把检查表、工具清单或逐字思维复制进成品。

### 模块切换与读取边界

按尚需完成的判断与组织工作区分轻重，不能只看答案字数或用户是否说了分析、写作：

| 当前工作 | 读取与执行要求 |
| --- | --- |
| **轻量表达或核对**：已有事实、判断与证据边界足够，仅做压缩转述、局部措辞、标题或格式调整，或明确口径下的直接计算 | 沿用当前上下文完成，无需为输出形式变化重新加载另一模块；仍遵守质量底线，出现实质缺口时升级 |
| **实质分析**：需要解释未明机制、比较竞争解释、处理关键取舍，或补足会改变结论的证据关系 | 首次进入时读取 [thinking-analysis.md](thinking-analysis.md)，再按缺口选读方法资料；写作中发现此类缺口也适用 |
| **实质成文**：需要重新确定主张或读者定位、组织长文的论据与结构，或重构笔记和知识框架 | 首次进入时读取 [writing-creation.md](writing-creation.md)，再按产物加载专门规则；分析结束后转入此类工作也适用 |

同一会话已经读取、内容未变且覆盖当前需要的模块可以直接复用，不为续接任务重复阅读。已有分析压成一段话可以走轻量路径；一段话若需要重新判断或组织论证，仍按实质工作处理。验收看判断、边界、结构和保全要求是否落实，不用文件读取次数代替成品质量。

## 写作内部的产物分流

需要实质成文的文本产物先由 `writing-creation.md` 接管共同的任务、读者、位置、事实、结构、表达和修改要求，再根据用途加载专门资料；轻量表达或核对遵循上方边界：

- **笔记、会议记录、课程与书籍整理、主笔记和知识框架**：读取 [笔记处理方法](references/note-processing.md)，由笔记类型、输入成熟度、保全要求、来源边界和长期用途决定具体做法。
- **文章、公众号、随笔、研究技术文本、职场汇报、述职发言、公文和组织文本**：按需读取 [文体与场景写作指南](references/writing-genres-and-scenarios.md) 的命中章节。
- **标题、局部改写、语言审阅或排版**：只进入对应局部能力，不重跑完整形成过程。

笔记是一组复杂的文本产物，不是单一文章模板。记录型笔记可以不建立作者立意和声音，但必须准确、完整、可追溯；面向读者的主笔记和专题框架同时接受通用写作、结构、语言与 Markdown 约束。

## 横向分析层的进入条件

出现以下信号时，进入或重新进入思维分析：

- 主题或对象不清，不知道真正要回答什么。
- 素材很多但没有主线，条目之间只有并列关系。
- 结论存在，但证据、机制、边界或现实代价不足。
- 选题或结构摇摆，无法判断读者为什么会在意。
- 笔记整理后仍只能回答“讲了哪些点”，不能回答“通过什么结构解决什么问题”。
- 草稿的 AI 味来自判断空洞或机制断裂，而不只是句式、节奏和措辞问题。

这些信号是导航证据，不是进入分析层的资格条件。即使没有命中固定表述，只要中间结果暴露出未解释的关系、相互竞争的判断、关键不确定性或现实反馈缺口，就可以临时插入分析；分析取得足够增量后再回到原主任务。反过来，用户信息已经足够且只要直接交付时，不为执行一套方法而强行追问或重跑前置分析。

若 AI 味只是模板句、结构过整齐、重复解释或局部表达问题，直接进入写作模块和 AI 味 reference，不必调用完整分析链。

## 完成条件

- **思维分析**：按当前请求完成解释、比较选择、探索或写作补充，交代具体依据与重要边界；理解增量、核验原判断或明确暂不可区分的解释都可以成立。下一步验证或行动只在任务需要时提供，详见 `thinking-analysis.md` 的完成标准。
- **文本写作**：完成真实产物要求。记录准确可追溯，笔记达到目标保全与重组强度，文章的核心判断、证据、结构和作者声音成立，正式文本与位置、授权和行动接口匹配。

完成条件满足后即可交付。输出结构服从任务，不默认附加工具清单、三个标题、行动召唤、金句、总结或方法论升华。

## 质量底线

- **高优先级表达约束**：本 Skill 新写或改写的自然语言不用中文或英文双引号，不用 `不是……而是……` 及同构对照句。正文、标题、摘要和过程说明均从起草时遵守，交付前复查；仅机器语法与必须逐字保真的内容按 [反 AI 味审阅](references/anti-ai-smell.md#高优先级表达约束) 处理，不能以文体或修辞需要为由放宽。
- 一个主线讲透，强于多个工具或观点并列。
- 不虚构事实、经历、数据、来源立场或作者情绪。
- 不把整理过程、文件任务和工具选择写成知识正文。
- 不用模板化结构替代真实判断，也不为“活人感”强行添加口语、故事或第一人称。
- 面向真实交付物写作：记录要准确，框架要可调用，文章要可信且值得读。
